# 报告模板 — Phase 评审

生成报告时严格使用以下结构。`<...>` 为占位符；状态只用 ✅ / 🟡 / ❌；证据必须具体（路径、测试名、命令输出摘要），不接受"已实现"这类无证据表述。

```markdown

更新日期：<YYYY-MM-DD>

| 项 | 值 |
| --- | --- |
| Phase | <N — 名称（docs/codex/research/06 §1）> |
| 评审日期 | <YYYY-MM-DD> |
| 代码基线 | <git rev-parse --short HEAD 或"未提交（untracked 工作区）"> |
| 总分 / 等级 | **<score> / 100 — <等级>** |

## 1. 验收标准核对

来源：docs/codex/research/06 §1 Phase <N> 的验收行与范围条目（原子化后共 <n> 条）。

| # | 验收条目 | 状态 | 证据 |
| --- | --- | --- | --- |
| 1 | <条目> | ✅ | <路径 / 测试名 / 命令输出> |

（门槛条目 = 验收行拆出的条目，表格中用 **加粗** 标记）

## 3. 质量门实测

## 6. 风险与下一步建议

1. <最重要的风险或缺口>

（本节只给建议；是否执行由人决定。）
```

## 写作要求

- 全部使用"参考工程"称呼对比对象，禁止出现其原名。
- 对比表"参考工程"列只写要点，标注事实出自 01/02/03 哪份文档（如"01 §3"），不复制大段原文。
- 对比表"E-pig"列必须能被本报告 §1/§3 的取证支撑；凭印象写现状 = 评审作废重来。
- 评分表的"计算"列必须展示算式，使分数可独立复算。
- 报告正文中文；命令、路径、状态标签保持原样。
