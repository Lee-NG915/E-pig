# Figma to Code 流程图设计

## 目标

制作一张面向产品与业务方的 Canvas 流程图，让读者在一分钟内理解从 Figma 设计到可交付页面的关键路径。图中只保留关键决策、阶段产物与验收边界，尽量不使用工程术语。

## 结构

- 主叙事采用横向旅程地图：看懂设计 → 规划页面 → 对齐规则 → 变成页面 → 体验验证 → 交付候选 → 发布与业务验收。
- 每个阶段用一张卡片表达输入、关键动作和产物；阶段之间使用粗实线箭头。
- “规则确认”“体验通过”“发布状态”作为深色门槛节点，帮助读者识别需要确认的地方。
- 从体验验证回到对齐规则使用虚线反馈箭头，表达真实的设计—实现迭代。
- 底部单独放交付状态带，将检查通过、预览环境、线上发布、业务验收按证据顺序排列，明确这些状态不是同一个完成信号。

## 视觉语言

使用 E-pig 的 cream 页面底、moss 主线和 mono 深色文字。卡片保持较大留白，使用简单线性图标；不使用渐变、复杂装饰或默认科技蓝。图例说明实线主流程、虚线反馈回路、深色门槛节点和底部交付状态带。

## 交付形式

独立 HTML 文件使用原生 `<canvas>` 绘制，并保留可读的文本图例与阶段数据。画布按窗口宽度缩放，便于在浏览器中演示；不依赖额外运行时或外部资源。

## 验收

- 读者能按主箭头顺序复述完整流程。
- 能一眼找到三个关键门槛：规则确认、体验通过、发布状态。
- 能区分主流程和反馈回路，并理解交付状态的先后关系。
- 在桌面和窄窗口下仍能阅读标题、阶段名、产物和图例。
