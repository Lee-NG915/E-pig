# M2.1 PRD — Home 升级 + PLP

更新日期：2026-07-18

状态：proposal  
Phase：2  
依赖：Phase 1 完成  
参考工程锚点：Home 服务端抓取；`(PLP)/` 列表与 product services（01 §2.2、§4）

## 1. 目标

把 Phase 1 的 Home demo 提升为可扩展的生产级信息架构入口，并新增 **PLP（商品列表页）**：按类目/集合浏览 mock catalog，支持最小筛选或排序之一，列表可进入 PDP（M2.2）。

## 2. 范围

- Home：分区清晰（hero / 精选 / 入口到 PLP），数据来自 CatalogPort（可仍 mock）。
- 路由：如 `/collections/[slug]` 或 `/products`（实现时选定一种，写入 AGENTS/路由表）。
- PLP：服务端取数 + 列表 UI（复用/扩展 `product-card`）；空态与加载态。
- 最小筛选 **或** 排序（二选一即可关门；另一个可 stub）。
- 市场价展示延续 Phase 1（货币/locale 来自 market registry）。
- 组件测试：PLP 关键空态/有数据态；Home 入口可测。

## 3. 非目标

- PDP 完整页、variant、搜索页、server cart、CMS page builder、Elasticsearch。

## 4. 验收标准（phase-review A）

| # | 条目 | 门槛 |
| --- | --- | --- |
| 1 | 存在可访问的 PLP 路由，mock 数据下列表非空 | **是** |
| 2 | 列表项展示名称、价格、主图（或占位）、链向 PDP slug | **是** |
| 3 | Home 至少一处导航进入 PLP | **是** |
| 4 | 实现筛选或排序之一，行为有测试或可演示 | 否 |
| 5 | 空集合有明确空态 | 否 |
| 6 | modules 不 import adapters；经 registry/port | **是** |
| 7 | `pnpm typecheck` / 相关测试绿 | **是** |

## 5. 参考工程对齐要点

- 复现「列表在服务端组装、卡片可进详情」的意图。
- 不复制 PLP 上全部 facet/DY/个性化。

## 6. 风险

- Listing DTO 若与 Search（M2.3）分叉，后续合并成本高 → 先冻结契约（见 phase-2 README §4）。
