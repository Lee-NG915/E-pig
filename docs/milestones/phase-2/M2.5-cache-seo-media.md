# M2.5 PRD — Cache / SEO / 媒体策略

更新日期：2026-07-18

状态：proposal  
Phase：2  
依赖：M2.1–M2.2 页面稳定；与 M2.4 对齐「何为不可缓存」  
参考工程锚点：生产 Redis ISR（01 §4）— E-pig **显式** Cache Components；shared SEO 能力

## 1. 目标

为公开浏览页建立：

1. **缓存策略**：哪些用 `'use cache'` + `cacheLife` + `cacheTag`，哪些 request-time  
2. **SEO**：title/description、canonical、基础 structured data（Product/Breadcrumb 择要）  
3. **图片**：`next/image`（或等价）尺寸/优先级约定，避免巨大原图

## 2. 范围

- 文档化 cache 矩阵（Home/PLP/PDP/Search 片段 vs cart）。
- 至少 2 个公开数据路径真正使用 `'use cache'` + tag；失效函数或注释说明如何 invalidate。
- metadata API：PLP/PDP 至少有动态 title。
- Product JSON-LD 或等价（PDP）。
- 图片：远程 pattern 或本地 public；LCP 图 `priority`。
- 测试：cache 纯函数/tag 命名可测则测；SEO 字段快照或断言。

## 3. 非目标

- Redis cache handler、全站 ISR 旧语义、hreflang 多语言全集（多语言未开时只留扩展点）、完整 sitemap 生态。

## 4. 验收标准

| # | 条目 | 门槛 |
| --- | --- | --- |
| 1 | 书面 cache 矩阵（可在本 PRD 实现备注或 `docs/` 短文）与代码一致 | **是** |
| 2 | 至少两处 `'use cache'` + `cacheTag`，且 cart/price 敏感路径不在共享 cache | **是** |
| 3 | PDP（或 PLP）动态 metadata 有 title | **是** |
| 4 | PDP 有基础 structured data 或明确 defer 记录 | 否 |
| 5 | 列表/详情主图走优化图片组件 | **是** |
| 6 | typecheck/test/build 绿 | **是** |

## 5. 参考工程对齐要点

- 复现「公开页可缓存、交易态不可乱缓存」；用 Next 16 显式模型替代 Redis 隐式 ISR。

## 6. 风险

- 错误 cache 商品价格 → 必须红线测试或 code review 清单。
