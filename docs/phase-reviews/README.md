# Phase Reviews — 里程碑评审报告

本目录存放**每个 Phase 完成时**的评审报告。评审不是自动发生的：由人确定"里程碑已完成"后，显式触发 `phase-review` skill 生成（见 `.agents/skills/phase-review/`）。

## 报告包含什么

1. **实现程度**：对照 `docs/codex/research/06` 该 Phase 的验收标准逐条核对，每条附可验证证据（文件路径、测试名、命令输出），状态只有 ✅ / 🟡 / ❌ 三种。
2. **未实现清单**：缺口项及其原因、归属的后续 Phase。
3. **质量门实测**：typecheck / lint / test / build / diff-check 的真实运行结果，不是推测。
4. **与参考工程多维度对比**：架构形态、渲染缓存、多市场、状态数据、UI 体系、测试质量、可观测性、部署运维、功能完整度等维度，逐项给出胜负与理由——劣势维度必须如实写负。
5. **评分**：按统一 rubric（实现度 50 + 质量门 20 + 架构符合度 15 + 对比净优势 15）计算的百分制得分与等级。

## 命名与更新约定

- 文件名：`phase-<N>-<slug>.md`（如 `phase-1-minimal-skeleton.md`），一个 Phase 一个文件。
- 同一 Phase 重新评审时**就地更新**该文件并改文件头的`更新日期`，不新建文件；历史分数记录在下表。
- 报告头部必须有 `更新日期：YYYY-MM-DD` 行（遵循 `.agents/rules/doc-freshness.md`）。

## 触发方式

对 AI 说：**"跑一下 phase N 的评审"** / **"做里程碑评审"**。
AI 不会在完成开发后自行触发本流程——里程碑的时机由人决定。
